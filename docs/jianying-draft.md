# 剪映三轨草稿：结构、字段换算与校验

## 三轨结构

| 轨 | 片段粒度 | 规则 |
|---|---|---|
| 视频轨 | 段落（由句子合并而成） | 起点 = 上一段终点，时长 = 段落内句子时长之和；段边界必须落在句与句之间 |
| 音频轨 | **逐句** | 每句一段：`start` = 该句累计起点，`duration` = 该句时长 |
| 字幕轨 | 逐句（长句按标点再分短语） | 每条起止与该句严格对齐，短语之间按字数比例分配该句时长 |

三轨都**不合并成整段**。合并了就失去"逐段替换"的能力，也就失去了交给剪辑师继续改的意义。

## 段落规划（先规划，再构建）

目标：每段 ≈5s，且**不允许**某段过短（浪费素材）或过长（素材不够）。

```
短句（<4s）→ 并入相邻段
常规句      → 累计到 ≈5s 处收一段
超长句（>12.6s）→ 单独成段，配 241 帧（≈10s）素材
段数 > 素材数 → 合并最短的相邻两段，直到放得下
```

**绝对禁止**"总时长 ÷ 段数"的均匀分配 —— 那样切点必然落在句子中间。

## 素材适配

```
素材比段长  → speed=1.0，直接截到段长
素材比段短  → 慢放：speed = 素材时长 / 段时长，最低 0.4（= 2.5 倍时长上限）
慢放到 0.4 仍不够 → 重新生成更长帧数的素材（121 → 241），不要循环、不要定格
```

## 剪映 JSON 字段换算（最容易错的地方）

剪映界面显示的数值与 `draft_content.json` 里的字段**不是 1:1**：

| 项目 | UI 显示 | JSON 字段 | 换算 |
|---|---|---|---|
| 字号 | 6 | `materials.texts[].size` | 直接写 6.0 |
| 字间距 | 5 | `letter_spacing` | UI × **0.05** = 0.25（写 5.0 会显示成 100） |
| 行间距 | 1 | `line_spacing` | UI × **0.02** = 0.02 |
| 位置 Y | -800 | `segments[].clip.transform.y` | UI ÷ **画布高** = -800/1080 = **-0.7407**（写 -0.8 会显示 -864） |

`pyJianYingDraft` 的 `TextSegment` 构造参数里没有字间距，且属性赋值不落盘 →
**构建后必须直接改 `draft_content.json`**（`build_draft.py` 已经这么做了）。

## 交付前四道校验

1. `Σ句时长 ≈ 完整 wav 时长`（容差 0.1s）—— 时间轴本身自洽
2. `视频轨末点 ≈ 音频轨时长`（容差 0.1s）—— 两条轨没跑偏
3. 每段 clip 实际时长与目标误差 <0.15s —— 慢放/截取算对了
4. 段间无缝（段 N 终点 = 段 N+1 起点，<1ms）—— 没有空隙也没有重叠

四道全过才交付。

## 常见"改完没变化"

| 现象 | 根因 | 解决 |
|---|---|---|
| 改了素材但草稿没变 | clip 缓存按文件名复用 | clip 文件名带素材指纹：`seg{段号}_{md5(素材路径)[:8]}.mp4` |
| 单镜替换无效 | OVERRIDE 的 key 用错（段号 vs 镜头号） | 用显式字典 `{段号: 素材路径}`，并校验"唯一素材数 = 段数" |
| 核对过素材还是不对 | 看的是素材库，不是草稿实际引用的 material | 读 `tracks[].segments[].clip.material_id` → `materials.videos[].path` 逐段核对 |

## 已打开草稿时的重建

剪映会锁住正在编辑的草稿目录，且 6+ 版本对 `draft_content.json` 加密。
重建时**换新目录 + 新草稿名**，不要覆盖用户正在看的那个。
